# The Home's updates install with dex metadata, so they run compiled

Android discards an app's compiled code when the app is updated, and an app installed outside the Play Store runs from then on in `verify` state — interpreted and JIT-compiled — until the next background compilation, normally overnight while the TV is idle. On the owner's TV (2026-10-24) the same Home, version 0.4.8, measured 40% janky frames and a 44 ms typical frame in `verify`, and 1.2% and 15 ms once compiled with `speed-profile`. With several updates a day, the Home spent the day slow.

Android compiles at install when the installer hands it, next to the APK, a dex metadata file (`.dm`) holding the app's profile, as Play does. So each release carries one: `scripts/release.sh` turns the profile the build puts in the APK (`assets/dexopt/baseline.prof`) into `free-my-tv-<version>-tv.dm` with `profgen extractProfile`, in Android 12's profile format (the TV's), and publishes it beside the APK. The Home's updater downloads the `.dm` named like the APK and writes it into the install session as `base.dm`. On the emulator an install with it came out `speed-profile` (`install-dm`), without it `verify`.

The profile is the libraries' own (Compose's, some 8,700 methods) plus wildcard rules for the Home's code and TV Material in `app/src/main/baseline-prof.txt`, which bring it to some 11,500. If Android ever refuses the metadata, the update installs again without it: never compiled at install is better than never installed. An update installed by a version of the Home without this (0.4.8 and before) still arrives uncompiled.
